# PRD — 癫狂版 Hello World（从零重开发）

## 1. 背景与目标
在保留“Hello World”核心语义的前提下，打造一版**高冲突视觉 + 夸张动态 + 失真撕裂感**的实验性页面。目标是“看起来疯狂，但交互依然可用”。

## 2. 设计原则（硬约束）
1. 高冲突色彩（霓虹红/电光青/高饱和黄等）
2. 动态夸张（抖动、错位、脉冲、闪烁）
3. 视觉失真（glitch、scanline、chromatic aberration）
4. 超常规排版（大字号、旋转、重叠层）
5. **可读性与可用性不牺牲**（核心文案可识别，按钮可点击，动画可降级）

## 3. 用户故事
- 作为访客，我打开页面后立即感受到“癫狂冲击感”。
- 作为访客，我仍能清晰读到主文案“HELLO WORLD”。
- 作为访客，我可以切换/暂停部分动画，避免不适。

## 4. 功能范围
### 4.1 必做（MVP）
- 全屏 hero 区域，中心主文案 `HELLO WORLD`
- 至少 3 种视觉特效叠加：
  - 抖动（jitter）
  - 色差（RGB split）
  - 扫描线/噪点（scanline/noise）
- 交互按钮：
  - `PANIC ON/OFF`（总开关）
  - `SHAKE ++`（增强动效）
  - `CALM MODE`（降级动画）
- 响应式支持（桌面/移动）

### 4.2 非目标
- 不做后端服务
- 不做账号系统
- 不做多页面路由

## 5. 验收标准
1. 页面首屏 2 秒内可见主文案与交互控件。
2. 主文案在默认状态可阅读（对比度达标，无遮挡持续 >70% 时间）。
3. 三个按钮均可操作，状态切换有可见反馈。
4. `CALM MODE` 启用后，动画强度显著降低（频率/位移下降 >=50%）。
5. 无 JS 环境下仍展示静态文案与基本样式。

## 6. 技术约束
- 技术栈：原生 HTML/CSS/JS（轻量、可直接部署静态站）
- 动效优先 CSS，必要时用 JS 调节参数
- 保持文件结构清晰，便于 QA 复现与 Ops 部署

## 7. 风险与缓解
- 风险：过度动效导致眩晕/性能下降。
  - 缓解：默认中等强度，提供 `CALM MODE` 与 `prefers-reduced-motion` 兼容。
- 风险：视觉冲突影响可读性。
  - 缓解：主文字加描边/阴影/对比底层遮罩。
